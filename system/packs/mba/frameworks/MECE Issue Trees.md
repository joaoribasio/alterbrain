# MECE Issue Trees

**Definition:** MECE means Mutually Exclusive, Collectively Exhaustive. An issue tree splits a question into branches that do not overlap and together cover everything.

## When to use / when not to
- Use it to start a case, assignment or consulting problem.
- Use it to plan your analysis and split work in a team.
- Do not use it to hide a lack of ideas. Branches must be specific to the problem.
- Do not chase perfect MECE forever. Stop when the branches are useful.

## Inputs you need
- A clear, specific key question (see [[Pyramid Principle and SCQA]]).
- Basic facts or formulas about the topic.

## Step-by-step
1. Write the **key question** at the left, in one sentence with a clear success measure.
2. Choose a way to split it. Common splits:
   - A formula (profit = revenue - costs; revenue = price x volume).
   - A process (steps in order).
   - Parts of a whole (segments, regions, products).
   - A framework (for example, internal and external).
3. Draw 2 to 5 branches. Check:
   - **Mutually exclusive:** nothing sits in two branches.
   - **Collectively exhaustive:** nothing important is missing.
4. Split each branch again, until you can test it with data.
5. Mark the branches most likely to explain the problem (a hypothesis).
6. Plan the analysis for those branches.

## Common pitfalls (what professors mark down)
- Overlapping branches (for example "online" and "young customers").
- Missing a branch, which hides a likely cause.
- Branches with no common logic (a mix of a formula and a list).
- A tree so wide it says nothing.
- A tree that is never used to drive analysis.

## Worked example (synthetic)
Key question: "Why did the profit of a bakery chain fall 20% last year?"
- **Profit fell** splits into
  - **Revenue fell** = price x volume
    - Price: lower average price, more discounts
    - Volume: fewer customers, or smaller baskets
  - **Costs rose**
    - Variable: ingredients, packaging
    - Fixed: rent, staff, energy
Check: profit = revenue - costs, so the first split is MECE. Data show costs flat and customers down 15%. The team focuses on "fewer customers" and tests location, opening hours and a new rival.

## Questions to ask yourself
- Could one fact fit in two branches?
- If all branches were true, would the problem be fully explained?
- Is the splitting rule the same at each level?
- Which branch has the biggest impact?
