# 0022. A course starts by asking for all of its material

Status: accepted (2026-10-08, framework owner)

## Context
ADR 0021 moved course material to download-and-ingest, but the ask was weak. Onboarding M3 asked for the syllabus only, once per course, and mentioned the rest ("Bring your course material") in one step at the end. A course that starts later in the programme (MBA terms have several blocks) had no flow at all: `/reconfigure` sent "add a new course" back to the onboarding module, `/assignment new` created a bare course note without asking for any material, and `/ingest` did not set up a course that had no note. Excel models, data files, rubrics and past exams were never named, so a student had no reason to think they counted.

## Decision
- **One procedure for one course:** `system/packs/mba/course-setup.md`. It asks for everything as soon as the course is named, with a checklist (syllabus or course guide, slides, readings and reading list, cases, Excel models and data files, assignment briefs and rubrics, past exams or sample questions, announcements, anything else). Options are "Here's everything (zip or folder)" (recommended), "Only the syllabus for now" and "Later" (one task that carries the checklist and the download steps).
- **A new skill, `/course`,** is the entry point for a new course, block or term, and for looking at an existing course (its Material list and gaps). Onboarding M3 keeps its wrapper (school, programme, term, the list of courses, the summary) and follows the procedure for each course. `/reconfigure` sends "add a course" to `/course new`.
- **`/ingest` meets the procedure** instead of duplicating it: a course with no note is offered course setup (note, AI rule, deadlines), and a course with a note gets its Material list refreshed. `/assignment new` finishes the assignment interview first and then offers `/course new` in one line. `/weekly-review` asks once whether there is new material.
- **The course note holds a `## Material` index** of the course's source notes, grouped by type (syllabus, slides, readings, cases, data and models, assignments and rubrics, exams, other) and by session when the file makes it clear. Raw files are never moved: organising means notes and links.
- **No case notes at setup.** A case note carries `case_date`, which the reviewers' hindsight rule needs, and setup cannot know it. `/assignment new` creates the case note and settles the date.
- **A gap check follows the import** (no syllabus, an assignment without a brief or rubric, sessions without slides, a referenced Excel model not provided). It asks at most one question or adds one task, and never blocks.
- **Word, PowerPoint and Excel files are described without overclaiming.** `.csv`, `.tsv`, PDF and plain text are read. `.docx`, `.pptx`, `.xlsx`, `.xls`, `.xlsm`, `.ods` and similar are read only if the optional document reader (markitdown through `uvx`) is installed, and the Read tool cannot open them. The procedure therefore checks the reader before the copy (a file already copied is skipped on a second import, so installing later does not help it) and offers PDF first (recommended, nothing to install), install first, or copy as they are. Unreadable files are listed as "not readable yet", counted apart in the gap check and the summary, and never summarised from their names. Whether formulas, charts and speaker notes survive is [Unverified].
- **Finished courses stop being asked about.** `/course new` asks once whether earlier-term courses are finished and sets `status: "completed"` on a yes; the weekly review asks only about active courses and puts the answer that fits last week first.
- **A zip is never split by course.** `ingest.mjs` labels a whole run with one course and only the script opens zips, so a zip with several courses is unzipped by the student (one folder per course) or imported without a course.

## Consequences
- Students are asked for everything once per course, at the moment it starts. The cost is more questions in onboarding; "later" and "only the syllabus" keep it short, and one answer can cover all courses.
- Onboarding M3 no longer has a fixed 6-minute promise once files are handed over: it says 6 minutes for syllabi only and gives a labelled estimate for a full import.
- Deadline tasks from course setup carry `#ab/course` instead of `#ab/onboard` or `#ab/ingest`.
- The study blueprint's "course setup from a syllabus" extra became "session notes from a syllabus", because `/course` now covers the setup.
- Not tested: the procedure end to end with a real course zip, and what markitdown returns for real workbooks.

## Alternatives considered
- **Extend M3 only.** Fixes the first term and nothing after it. Rejected.
- **Ask for the material at the end of onboarding, as before, but name Excel and rubrics.** Cheaper, and still no flow for a later block. Rejected.
- **Create a case note for every case in the zip.** Needs a case date setup cannot know. Rejected in favour of the index.
- **A separate course-setup skill per entry point.** Four copies of the same steps would drift apart. Rejected: one procedure file, as for the voice import.

## Addendum: material keeps arriving (2026-10-08, framework owner)
Asking at course start is not enough: lessons, notes, cases and feedback arrive all term. Everything the student studies should end up in the vault.
- **A standing rule in `system/core.md`** (one line): when the user mentions or hands over anything new for a course, ask once, after their request, to have it and add it via `/ingest`. After review the rule reads: if something new for a course comes up and its Material list lacks it, ask once per course per session, after the user's request and never mid-draft ("item" was undefined and let the same course be asked about repeatedly). The detail (examples, how to infer the course, linking the user's own typed notes into the Material list under "Your notes" instead of importing them again) is `course-setup.md` section 7 and the `ingest` skill, not core.md, which is over its size budget.
- **Machine-readable class dates in the course note:** `session_dates` (only dates the syllabus states), or `class_days`, `term_start` and `term_end` (asked once when the syllabus has no dates). Empty by default, so older notes simply get no reminder. The question lives in one place, "The schedule question" in `course-setup.md` section 3, and is asked in `new`, in `refresh` only when a syllabus arrives, and in `review` (`/course <name>`) for an active course with no class dates, which is how a course set up earlier gets them. A "don't know" is recorded as `class_days_asked: "<date>"` so it is not asked again unprompted.
- **An after-class reminder in the session digest** (`system/lib/courses.mjs`): up to 3 lines "New material? <course> had class on Tue 13 Oct", most recent class first, one summary line for more than 3 courses. A class counts when it is strictly before today, or today from 18:00 local time, and lies within the last 14 days. Each class is mentioned once (`state/local/course-nudges.json`, never committed). The state is written only after the digest has been delivered, the lines use only the room the warnings leave, and every failure gives no lines.
- **Rejected:** a model-written guess at the class schedule (invents dates); a reminder for every day without material (noise); marking nudges as seen when the digest is built (a failed build would lose them); writing the state inside the vault (it would be committed and synced between computers, where "already said" is not true).
- **Bounds, after review:** a class on or before the note's `created` date is never reminded about (for `session_dates` as well as `class_days`: the student was bringing the course in that day, so reminding them about last week's class the next morning asks for material they just handed over; the cost is one missed reminder for a class later on the setup day itself). Generated class days start at `term_start` when given and stop at `term_end`; without `term_end` they stop 16 weeks after `term_start`, or after `created` when there is no `term_start`, and a schedule with none of those anchors is not generated, so a course that is never marked completed cannot be nudged for ever. 16 weeks covers a block (6 to 10 weeks) and a semester [Inference: typical MBA programme lengths]. Rejected: a task that asks the student to mark idle courses completed (the hard bound already ends the reminder, and the weekly review asks about earlier-term courses).
- **Not decided:** A headless session that reads the digest consumes the reminder without a student seeing it [Inference: Claude Code gives no flag to tell them apart].
