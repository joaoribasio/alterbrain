# 0026. Deliverables: one standard for voice, principles, the delivery gate, critique and model audit

Status: accepted (2026-10-08, product owner)

## Context
Before 0.2.0 only the assignment studio had a quality process: a blind reviewer panel, a final render and a page-limit check. A deck for work, a report with no rubric, a workbook, a CV or a memo got none of it, and the assignment process itself had gaps seen in real use:

- A file passed Alterbrain's checks and was still not ready: a cover with a placeholder instead of the teammate's name, `[Inference]` left in a deck, a file name that broke the course rule, a workbook that opened with uncalculated cells, a PDF too big to upload, a deck whose numbers disagreed with the report.
- A helper reported that it had "viewed all pages", and the main session believed it.
- Voice was applied to emails, not to deliverables, and tone (how formal) was not a setting at all.
- Slides were built before the argument was agreed, so the title of each slide described a topic instead of stating a point.

## Decision
- **Voice is always on for a deliverable,** from the user's voice profile for that language. With no profile, the skill says so once and suggests the voice setup instead of using a neutral house style. **Tone is a formality dial on top**: `academic`, `professional` or `conversational`, set per programme, course, project or assignment with a recommended default, overridable per deliverable. Storytelling is the default inside the structure (situation, complication and answer as a narrative; answer first, then stakes; a real person or customer moment; concrete specifics; contrast; a close that calls back to the opening). Guardrails: no invented anecdotes, academic tone keeps the story quieter, a rubric or school template that prescribes a structure wins. For group work, one question per deliverable: "sound like you, or a neutral team voice?" (`voice_mode`).
- **One set of principles** in `system/deliverables/principles.md`, used by drafting, the delivery gate and the structure lens: Minto pyramid and SCQA, MECE, storyline first (the user approves the ghost deck of action titles before slides), action titles, horizontal and vertical logic, one message per slide, executive summary up front, chart and number rules, reading deck against presenting deck, Duarte's arc, hooks and stakes. Cheap mechanical checks (slide titles as sentences, a source line, the template's house rules) run in the gate; judgement goes to the structure lens.
- **One delivery gate** (`system/deliverables/delivery-gate.md`, `deliver-check.mjs`) before the user is told to upload, for every file type: the cover or title slide is complete, file names follow the course or template rule and share a base name, every page has been viewed, the workbook opens with calculated values and no error cells, report, deck and workbook agree, the size is within the upload limit, and no labels or placeholders remain. Then the submit task. Alterbrain never uploads.
- **The main session looks itself (C1, C4).** It views every page of a deliverable; a helper's "viewed all" is never evidence, and delegated work is never reported done on a helper's word: the main session reads the diff and looks at the changed pages. Pages come from `pages.mjs`, which renders PDFs with Poppler's `pdftoppm` and exports Word, PowerPoint and Excel files to PDF through the Office app (LibreOffice as the fallback, with a plain warning that fonts may differ).
- **No bracket labels leave the computer (C2).** `[Inference]`, `[Unverified]`, `[Speculation]`, `[FACT NEEDED]` and placeholders such as `[Teammate name]` stay in chat and working notes. In a deliverable they become plain wording ("we assume", "in our reading") or a filled-in fact. `release-scan.mjs` reads text, `.docx`, `.pptx`, `.xlsx` and PDF text and fails on them, and a file it cannot read counts as failed, not clean. This sits beside, not instead of, the labels rule for chat in `core.md`: the boundary is one sentence in "Known vs not known".
- **Critique for every deliverable.** `/critique` runs the panel on any file; `/assignment critique` uses the same procedure and the same single lens library (`.claude/skills/critique/references/lenses/`). Lenses: devil's advocate, premortem, board, specialists, grader (only with a rubric), fact-check, structure, signature (does it sound like the user, does it have story and stakes, would the audience care), production (layout and consistency across files), model audit (workbooks), recruiter (CV and cover letter), and the consolidation pass. The lens choice adapts to the deliverable type; a quick panel (two or three lenses) or a full panel, with the usage cost on Pro said plainly. It is offered once at the end of every deliverable flow; routine emails and messages are not offered it but can ask. The MBA pack adds business presets.
- **Model audit for workbooks.** A lens plus a light, zero-dependency check script (`workbook-check.mjs`): error cells, uncalculated formulas, typed numbers in formulas as advice, sheet list; recalculation through Excel only on Windows when Excel is installed and not open. Python builders and a second-verifier stage stay out of the default.
- **The rest of the standing fixes** (C5 to C12 and H1, H2): offer `/learn` when the user states a standing rule; show unsupported file types in Obsidian; a plain fix for a half-finished rebase or merge; the team recorded once per course; both sources shown when a deadline, weight or limit disagrees, and pasted assignment text saved word for word; import safety for files that forbid AI use, client or company material and rosters; bulk import where helpers write source notes only; an optional AI-use log; grades and feedback recorded and fed back into the course note; an optional rehearsal pack after a deck is approved.

## Consequences
- More happens at the end of a piece of work. The gate is mostly scripts, and the page review is the main session's own time and usage. On Pro, the quick panel is the recommended critique and the full panel costs noticeably more; the skill says so before it runs.
- A deliverable can now fail a check that the user's rubric contradicts (a prescribed slide title). The waiver mechanism (`--allow-titles`, `--skip-checks`) exists for that and every waiver is told to the user and written in the hand-over. The label scan cannot be waived.
- The delivery gate needs a PDF page renderer on the computer to look at pages. The health check and setup offer it once, never mid-task. [Unverified] Whether Claude's Read tool can open PDF pages without it; Alterbrain renders the pages itself.
- The `lens` agent and `/assignment critique`'s old reviewer calls are replaced by the named helpers (ADR 0027). The lens briefs moved to the critique skill (see the CHANGELOG, "Moved").
- Checks of the label scan are a deliberate, documented gap: a capitalised bracket that is not on the placeholder list (for example `[Client]`) still passes, because the generic rule would fail common unit labels such as `[EUR m]` with no way to waive them.
- The standard is only as good as its looking. The main session's page review, the one thing no script replaces, depends on the model actually opening each image.

## Alternatives considered
- **Leave critique to the assignment studio.** Smallest change, and it leaves every non-graded deliverable (the ones the user is judged on at work) with no review. Rejected.
- **Make the gate a hard block.** A file that fails cannot be called ready. It is, apart from a waived check, and the user still decides what to upload; Alterbrain cannot see the school's portal.
- **A neutral house style when there is no voice profile.** Always produces something. Rejected: the user asked for a twin that sounds like them, and a neutral draft passed off as theirs is worse than a clear prompt to set the voice up.
- **Trust the helper's report of the pages it viewed.** Cheap. Rejected after a real miss; the reviewers are blind and read-only for a reason, and the main session is the one that answers to the user.
- **A separate lens library per skill.** Two copies of the same briefs drift apart. Rejected: one library, one panel procedure.
- **Python builders and a verifier agent for workbooks.** Heavy and against the zero-dependency core (principle 7). Rejected for the default; an add-on can offer them.
