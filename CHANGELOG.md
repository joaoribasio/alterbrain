# Changelog

All notable changes to Alterbrain are listed here. Newest first.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versions follow [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Changed
- Framework developers only: the regular test run is much shorter. The 288 slowest tests (2 seconds or more each, about 89% of the time) are now release tests: they are skipped unless the environment variable `ALTERBRAIN_SLOW_TESTS` is `1`, and are run by hand before a release. The automatic checks (CI) now start only when `system/`, `.claude/`, `tests/`, `.github/`, `CHANGELOG.md`, `CLAUDE.md`, `.gitattributes` or `.gitignore` change, and run the quick set. Nothing changes for learners.

## [0.2.1] - 2026-10-08

### Fixed
- The automatic checks (CI) no longer run in your notes repository. Your copy includes the framework's check workflow, and every automatic save is a push, so each save started a long Windows and macOS test run that only checks framework code you never edit, using up the free GitHub Actions minutes of a private repository. The workflow now runs its checks only in the framework's own repository; a push that changes only `vault/`, `config/` or `state/` starts no run at all; and a newer push cancels a run still going on the same branch. The update replaces the workflow file for you.
- Three upload-check tests failed on GitHub's Windows machines (red CI since 0.2.0, also in notes repositories that run it). They chose Git for Windows' `bin\sh.exe`, a launcher that puts Git's own folders back on the PATH, so the real `git` and `git-lfs` hid the restricted PATH the tests build. The tests now use Git's plain shell (`usr\bin\sh.exe`), never the launcher, check that the restricted PATH really holds before testing (and skip with the reason if it does not, so they test the hook rather than the computer), and log which shell ran. The upload check itself was not affected.

## [0.2.0] - 2026-10-08

A major release: Alterbrain now works for anyone who learns or works, not only MBA students, and gains a template engine, critique for every deliverable, a contact book, routines and upgrades that ask first. From this version the licence is PolyForm Shield (see Changed). Update with `/update-alterbrain`; it walks you through the upgrade questions.

### Added
- Routines (ADR 0030): a registry of your scheduled jobs. Each job is one note in `vault/90_routines/` with its schedule, where it runs (laptop, Claude cloud or a server), the exact instruction it follows, and when it last ran and what happened. Alterbrain still runs no scheduler: the Claude app or your server does. The notes make a job visible in Obsidian (new `Routines.base` view), easy to move to another computer by copy and paste, and noticeable when it stops: the start-of-session summary, the health check and the weekly review say which routines are late. Routines only prepare drafts and tasks; nothing is sent. `routines.mjs` has `list`, `overdue`, `show`, `record`, `suggest` and `enable`; three suggestions ship as templates (contacts due, weekly review reminder, morning brief), and `/build` writes a routine note for every automation. New guide: "Routines: your scheduled jobs".
- A weekly notice when a newer Alterbrain exists. At the start of a session, if the last look was a week ago or more, Alterbrain asks GitHub for the newest public release number (nothing about you is sent), and if it is newer than yours the start-of-session summary gets one line: "Alterbrain vX is available. Say 'update Alterbrain' when you're not mid-assignment." It never installs anything. Offline or on any error it says nothing and tries again next session. `/update-alterbrain` still works any time, and `ALTERBRAIN_UPDATE_CHECK=off` turns the notice off.
- Upgrades that ask you first ("guided upgrades", ADR 0027). Some upgrades need judgement about your own notes, so a script should not do them alone. A release can now include a short written upgrade that your own Claude follows after the update: it looks at your notes, proposes what makes sense, changes only what you approve, and lets you skip it or run it later. `/update-alterbrain` lists them before you agree and walks you through them afterwards, one at a time. A restore point is saved first, as for the other upgrades. New command: `update.mjs guided list|savepoint|done|skip`; the answer is recorded in `state/migrations.json`.
- Four named helpers, one for each kind of work (ADR 0027): `helper-triage` (small sorting and extracting, the small model), `helper-draft` (notes, summaries and edits, the middle model), `helper-review` (blind, read-only checking, the middle model with more effort) and `helper-judgement` (the few hard judgement passes, the largest model). Every skill that used to ask for an ad-hoc helper in a sentence now names the right one, and `validate.mjs` fails if a skill does not. The old `lens` helper still works and is retired no earlier than 0.4.0.
- Deliverable quality for every report, deck, workbook, memo, CV and letter (ADR 0026), in the new folder `system/deliverables/`:
  - **Look at every page.** Before a file is called ready, Claude itself looks at every page or slide (cover, edges, half-empty boxes, wrong fonts, overlaps, small text); a helper saying it did is never taken as proof. `pages.mjs` makes page pictures from a PDF (it needs the PDF page renderer Poppler, offered once by the health check and setup, never in the middle of a task) and exports a Word, PowerPoint or Excel file to PDF through the Office app on your computer, or LibreOffice with a warning that fonts may look different.
  - **No working labels in what you hand in.** `[Inference]`, `[Unverified]`, `[Speculation]`, `[FACT NEEDED]` and placeholders such as `[Teammate name]` stay in chat and working notes; in a deliverable they become plain wording ("we assume", "in our reading") or a real fact. `release-scan.mjs` reads text files, Word, PowerPoint, Excel and PDF text and fails on any it finds; a file it cannot read counts as failed, never as clean.
  - **One check before you upload.** The cover or title slide is complete (names, programme, no placeholder), file names follow the course or template rule and share one base name, every page has been looked at, the workbook opens with calculated values and no error cells, the report, deck and workbook agree on the headline numbers and terms, the file fits the upload limit, and the label scan is clean. Then a task for you. Alterbrain never uploads. `deliver-check.mjs` does the mechanical part.
  - **Delegated work is never reported done on a helper's word.** Claude reads the changes and looks at the changed pages itself.
  - **A standing rule becomes a lesson.** When you state a rule that should always hold, Claude offers `/learn` in the same turn so it is saved in `MEMORY.md`, not only in Claude's own memory.
  - **Obsidian shows Word, PowerPoint and Excel files** in the file list (see Changed).
  - **A plain fix for a half-finished git rebase or merge.** The health check spots it (the automatic save refuses until it is cleared) and gives the one command that undoes it.
  - **Your team is recorded once per course** (names, team name, team number) and reused for covers, title slides and file names. A "[Teammate name]" placeholder never ships.
  - **When two sources disagree** on a deadline, weight or limit, Claude shows both and asks; it never picks one silently. Assignment text you paste is saved word for word.
  - **Safer imports.** A file that says it must not be used with AI tools is flagged once and no note is written until you decide (`ingest.mjs --ai-pending` and `--ai-decide`). Client or company material gets a reminder to keep a private backup. A roster becomes business facts only.
  - **Bulk import** has helpers write source notes only, on separate files; Claude writes the wiki pages, index and log itself and checks one helper note.
  - **An optional AI-use log** for courses that require one: one dated line per working step, with your own part added only in your words. Offered, never forced.
- A critique for any deliverable (ADR 0026). The new `/critique` skill runs a panel of blind reviewers on any file (report, deck, workbook, memo, proposal, CV, cover letter, essay) and applies only the changes you approve. One library of reviewer lenses serves both `/critique` and `/assignment critique`: devil's advocate, premortem, audience or decision-maker, fact-check, structure (answer first, MECE, storyline, action titles, the template's house rules), signature (does it sound like you, does it have a story and stakes), production (layout and consistency across files), model audit (workbooks), grader (only with a rubric) and recruiter (CV and cover letter). The lens choice follows the type of file. A quick panel (two or three lenses) or a full panel; on Pro the usage cost is said plainly first. It is offered once at the end of each deliverable (render, assignment, job application, project deliverable); routine emails and messages are not offered one, but you can ask. The MBA pack adds business presets. Reviewers run on `helper-review`, and the full panel is consolidated by `helper-judgement`.
- Tone and your voice (ADR 0026). Deliverables are always drafted in your own voice from your voice profile; if there is none, Claude says so once and suggests the voice setup instead of using a neutral house style. Tone is a formality dial on top of your voice, never a replacement: academic, professional or conversational, set for a programme, course or project with a recommended default and changeable for one deliverable. Inside the structure Claude tells it as a story by default: answer first, then the stakes, a real person or customer moment, concrete specifics, contrast, and a close that calls back to the opening. It never invents an anecdote or a fact, academic tone keeps the story quieter, and a rubric or school template that prescribes a structure wins (Claude says so in one line). For group work it asks one question per deliverable: "sound like you, or a neutral team voice?"
- Presentation and document principles (ADR 0026), built in and checked by default: answer first (Minto pyramid, SCQA), MECE, the storyline of action titles agreed before slides are built, full-sentence titles of at most two lines, titles that tell the story alone and a body that proves each title, one message per slide, an executive summary up front and backup in an appendix, chart choice by message with the key number highlighted and direct labels, chart titles that state the so-what, a source line on data slides, consistent numbers and units, colour-blind-safe contrast and a minimum font size, speaker notes and timing, reading decks against presenting decks, and the what-is and what-could-be arc. A template or rubric structure wins when they differ.
- Templates (ADR 0025). A template is a folder with a `template.yml` (name, kind, style, upload limit, page limit, fonts, house rules, citation style, optional Word or PowerPoint reference file or Quarto extension, source). The four built-in templates now have one, and your own live in `vault/80_me/templates/<slug>/`. A template can be attached to a deliverable, project, course or programme, or set as your default for a kind of document; the most specific one wins, and `/render` says in one line which it used (it asks only if two tie). The new `/template` skill makes a template from a PowerPoint, Word or Quarto file you give it (reading colours and fonts from the file, checking the slide layouts Quarto needs, rendering a sample and looking at every page), and also lists, attaches, previews and removes. `template.mjs` has `list`, `show`, `resolve`, `check` and `inspect`; `render.mjs` takes `--template`, `--reference-doc` and `--csl`. Your personal look in `vault/80_me/brand/` keeps working as your default. School artwork is never part of Alterbrain.
- Grades and feedback (H1). When a grade or feedback comes back, drop it in: `/assignment feedback` saves it word for word, updates "How this instructor grades" in the course note and offers a `/learn` lesson. The weekly review asks about returned work.
- A rehearsal pack (H2), offered once after a deck is approved: speaker notes in your voice, a timing plan, the ten likeliest audience questions with short answers, and a one-page cheat sheet. Speaker notes follow the same rules as anything that leaves your computer.
- A model check for workbooks (I). The new `model-audit` lens asks whether every number in the report or deck maps to a cell, inputs are kept apart from calculations, no number is hidden inside a formula, there are no error cells or circular references, units and periods agree, self-confirming checks are named as such, and totals and signs make sense. `workbook-check.mjs` lists the sheets and flags error cells, formulas that were never calculated and numbers typed inside formulas; on Windows with Excel it can also recalculate a copy. It needs no extra software.
- A contact book for networking (J, ADR 0028). `/people` adds a person from an email signature, a LinkedIn profile you share, an event, a business card or a conversation, keeps a small profile in the person note (role, organisation, how you met, last contact, next follow-up, how often to keep in touch, tags, an interaction log), logs contact, and drafts a message in your voice (never sent). `people.mjs due` and the weekly review list who you should get back to. A new `Contacts.base` view shows it in Obsidian. It looks someone up in public sources only when you ask. Business facts by default; sensitive details only if you ask and never in outbound text; a birthday only if you add it. A blueprint for later, `keep-in-touch`, describes watching for news and job changes to draft congratulations (draft only, official data or your own exports, never scraping).
- Optional encryption of your most private notes before they reach GitHub (ADR 0019): onboarding and `/reconfigure` can switch on git-crypt for your fact sheet, `USER.md`, `MEMORY.md`, voice files, people notes and journal, so a leak of your GitHub account no longer exposes them, while the files stay normal on your laptop. `vault-key.mjs` sets it up, saves a copy of the key file outside the project (optionally protected by a password you type in a terminal, never in the chat), tests that copy, and unlocks a new computer. The automatic save never stages private notes it cannot encrypt, leaves out any that would be stored as plain text, and refuses to upload if one slipped through (this check stops the upload if it cannot run). `doctor` and the session digest report a locked copy, a missing tool and an untested key copy. New guide: "Encrypting your private notes".
- Encryption follow-ups (ADR 0019). Private documents are encrypted too: the PDFs, Word and Excel files, slides and pictures you keep in the private folders are scrambled like notes, because ordinary documents are no longer in Git LFS (see Changed). A new upload check closes the Obsidian Git gap on a computer: Git itself runs it before every upload (a small `pre-push` hook that `vault-key.mjs setup`, `unlock` and each Claude session keep in place), so Obsidian Git can no longer upload a private note or document without encryption. It stops the upload if it cannot run, it leaves another tool's hook alone, and it still lets Git LFS upload big files (like Git LFS's own check, it refuses to upload from a folder that uses Git LFS when Git LFS cannot be found). It looks only at what your computer would add, so notes that your phone put online do not block an upload, and it reads big files without loading them. It does not cover Obsidian on a phone. `vault-key.mjs status`, the health check and the session digest report it. The encryption tool (git-crypt) is now found straight after a winget install, without restarting the Claude app. A private file of 50 MB or more cannot be both encrypted and in Git LFS, so it stays off the online backup, with a task.
- `/course`: a course now starts by asking for everything you have (ADR 0022). Naming a course, in onboarding or later with `/course new` (a new block or term, or a course you add), makes Alterbrain ask once for the syllabus, slides, readings, cases, Excel models and data files, assignment briefs and rubrics, past exams and announcements. A zip or one folder per course is best, files one by one also work, and "only the syllabus" or "later" are fine (later adds one reminder task with the download steps). It keeps an untouched copy of every file, reads the syllabus for the grading, submission rules, deadlines and the AI rule (you confirm the reading), and keeps a **Material** list in the course note, grouped by type and session. It then says what is missing (no syllabus, an assignment without its brief or rubric, sessions without slides, an Excel model the course refers to) and asks at most one question or adds one task. Word, PowerPoint and Excel files are read only if the optional document reader (uv) is installed. Alterbrain checks that before it copies anything and, if it is missing, offers to save the files as PDF first (recommended), install the reader first, or keep them unread; unreadable files are listed as "not readable yet" and never summarised. PDF, CSV and plain text need nothing. One procedure, `.claude/skills/course/references/course-setup.md`, is followed by `/course`, onboarding M3 (which no longer holds its own copy of the steps), `/ingest` (offers course setup when the course has no note, refreshes the Material list when it has one) and `/assignment new` (offers it in one line after the interview). `/reconfigure` sends "add a course" to `/course new`, `/weekly-review` asks once a week whether there is new material, and the course template has a `Material` section. The "course setup from a syllabus" extra in the study blueprint is now "session notes from a syllabus".

- Course material keeps coming in all term, and Alterbrain reminds you after each class. Bringing in what you study is now a habit, not a one-off at course setup: whenever you mention or hand over something new for a course (a class that took place, slides, your own notes, a case, a reading, a brief, feedback, a transcript), Alterbrain checks the course's Material list and, if it is not there, asks once per course per session, after your own request and never in the middle of a draft, whether to add it to that course through `/ingest`, and it links notes you already typed in the vault into the course's Material list instead of importing them again. Course setup now records the class dates the syllabus states (`session_dates` in the course note) or, when the syllabus gives none, asks once for the weekdays of class (`class_days`, and `term_start` and `term_end` if you know them). A course set up earlier gets its class days the same way: say `/course <name>` and Alterbrain asks once, and remembers a "don't know" so it does not ask again. From those the start-of-session summary adds up to three lines such as "New material? Corporate Finance had class on Tue 13 Oct": a class counts once it is over (from 18:00 on the day itself), only the last 14 days count, classes on or before the day the course note was made are never mentioned, the reminder ends at `term_end` (or 16 weeks after the term starts if there is none), each class is mentioned once, and what was said is kept in `state/local/course-nudges.json` on your computer only. Courses without those fields get no reminder. The weekly review's weekly question stays. The guide "Bringing in your course material" has a new section, "When new material arrives".
- What you are learning or doing (ADR 0023). Setup now asks one question early: an MBA, a university degree, online courses (Coursera and the like), work with no courses, or something else. The answer is saved as `learner` in `config/brain.json` and sets the defaults for the rest. For online courses the AI-rule check applies only where a rule is found, and class days are asked only for courses with live sessions. For work with no courses there are no course or AI-rule steps: your focus areas go in `USER.md` and your projects in new project notes (`10_projects/<year> <project>/project.md`). An MBA keeps the 25 business frameworks; any other kind can switch them on later with `/reconfigure`. No packs are built ahead for degree, online or work learners: ask when you need one and `/propose` drafts it.
- Programme notes. One optional note per programme in `20_areas/programmes/` (for example `MBA – RSM`) holds what is true for every course in it once: the school or provider, level, terms, the school-wide AI rule, the grading scale, submission conventions and career services. Courses stay in `20_areas/courses/<course>/` and link to it with a `programme` property; a standalone course (Coursera) names its `provider` instead. The AI rule and the term dates are copied into the course at setup, the rest is read when it is needed, and the course's own value always wins. Two courses with the same name get a suffix ("Strategy (Coursera)").
- A new AI-rule value, `none-stated`. It means no rule was found in what was read, or you confirmed there is none, and Alterbrain then says nothing before assignments. It does not mean the provider's terms were checked, and Alterbrain says so when it sets it.
- Country packs, Netherlands first (ADR 0023). Job-search checks for one country live in `system/packs/country-<cc>/`. The Netherlands pack holds the sponsor-register, Dutch-language and salary checks. `/jobs` works in any country: without a pack it ranks on fit only and says so once. A pack you build yourself (`.claude/skills/my-country-<cc>/jobs.md`) is found too. Adzuna search works for any country Adzuna offers.
- Updates tell you about upgrades to your notes and settings. `/update-alterbrain` lists them before you say yes, runs them only after the restore point is saved (the update stops, and changes nothing, if Git cannot save one), and reports what each one did afterwards. A skipped upgrade is reported as a problem.
- Migrations and their policy (ADR 0024). Small numbered upgrade scripts change how your notes and settings are stored, once, when a release needs it. The rule for every release: a change to the shape of user data ships a migration or a documented fallback. The scripts are recorded in `state/migrations.json`, tested on fixture vaults and checked by `validate.mjs`, and `validate.mjs --release` checks these release notes before a release. Release 0.2.0 has seven: four scripts and three guided upgrades that ask you first (see Upgrades).

### Changed
- Licence: from this version Alterbrain is released under the PolyForm Shield License 1.0.0 (ADR 0029). You may use, copy and change it for any purpose, including study and work, but not to offer a competing product. Versions up to 0.1.1 stay under MIT. Contributions follow `CONTRIBUTING.md`.
- New blueprint `background-jobs.md`: choose how scheduled jobs (keeping in touch, update checks, a morning brief) run while you are away, from the laptop schedule to a free cloud server, with an optional small local model only for sorting. Nothing is chosen for you.
- The programme-note upgrade now asks you first. `0003-programme-note` was a script that would have made a programme note and linked your courses without asking. It is now a guided upgrade (ADR 0027): after the update Claude shows what it found, and you choose to do it now, later or never. Skipping it loses nothing, because the old school settings keep working.
- The yahoo-finance tool in the catalogue stays pinned to one exact version of its code (a fixed commit, because the project has no release tags), and its note now says what was checked. The package of the same name on PyPI (0.1.2, https://pypi.org/project/yahoo-finance-mcp/0.1.2/) was not adopted: its page links to no repository and the code was not compared with the pinned one, so it is [Unverified] whether it comes from the same author. This question is open for the owner.
- Obsidian now shows Word, PowerPoint and Excel files in the file list. Setup writes `showUnsupportedFiles` to the vault's settings; reopen the vault once, or say 'set up Obsidian again' for a vault you already have. [Unverified] The setting's name comes from community plugin sources, because Obsidian publishes no reference for it.
- Reviewers run on the named helpers. `/assignment critique` and `/jobs apply` use `helper-review` for the blind reviews and `helper-judgement` for consolidating them, `lite` panels are now called `quick`, and a reviewer lens is chosen by the type of file. The same switch was made in onboarding, study, build, the health check's model check and the other skills that used to ask for an ad-hoc helper.
- Git LFS is now only for big files (ADR 0020). Files of 50 MB or more (`git.lfs_min_mb` in `config/brain.json`) are stored with Git LFS; PDFs, slides, Word files, pictures and everything else are saved as normal files. That removes the Git LFS install step and its storage allowance for most people, and lets private documents be encrypted. The root `.gitattributes` no longer has Git LFS rules. For each big file the automatic save adds one exact-path rule to `vault/.gitattributes`, which is yours and is never replaced by an update. Files already in Git LFS stay there, and a changed one is stored as before. A big file that cannot be stored safely (Git LFS missing, in an encrypted folder, 2 GB or more, outside the vault) is left out of the backup, with a task. Obsidian Git is covered by a small check that Git runs before every save on a computer; a big upload carries on in the background after Claude closes; Git LFS files are uploaded before the saves that point to them. A phone's Git runs no checks, so an ordinary file of about 100 MB saved there pauses the online backup with a clear task instead of failing again and again. The health check gains `repo-size` (a tip from 1 GB of history, a warning from 4 GB), `big-file-hook` and `big-blobs`, and its Git LFS check now says it matters only for big files. The installers still provide Git LFS and switch the check on.
- Canvas is gone; course material now arrives by download and `/ingest` (ADR 0021). The `canvas-sync` blueprint, the `canvas-mcp` catalogue entry and the `school.lms` setting are removed, because some schools do not allow automated access to their learning platform. Onboarding (M3, "Bring your course material") now explains in plain words how to download everything from the course site (Files, select all, Download gives a zip) and how to save the syllabus and assignment pages as PDF, then hands over to `/ingest`. `ingest.mjs` opens `.zip` files and takes `--course "<Course name>"`. A zip is refused as a whole, and nothing from it is used, if it is password protected, damaged, holds a path that leads outside its folder or a link, holds two names that Windows and macOS treat as one file (for example `Notes.md` and `notes.md`), or is over 5000 files or 2 GB; a zip inside a zip is kept as a plain file and not opened. The `/ingest` skill has a course-material flow: it infers the course and asks once, links each source note to the course note, offers to put deadlines from a syllabus or assignment page into the course note and your task list, and works in batches of about 50 files. Study extras is now five add-ons.
- The core is learner-neutral (ADR 0023). Course setup, `/course`, ingest of course material, the after-class reminder, `/study` and the assignment studio are core: they no longer sit in the MBA pack or assume an MBA. The MBA pack keeps the frameworks library, the case method (`templates/case.md`), business reviewer presets and MBA wording.
- Assignments: a course is optional, and the target grade is asked in the course's own scale. `/assignment new` offers "No course" (first for someone who works), reads the AI rule from the course note and stores the target on the 10-point scale (pass/fail gets 7). The hindsight rule applies only to cases. The reviewer briefs are worded for any subject; business board seats and specialist examples are a preset that is used only with the MBA pack on. Study, `/framework` and the weekly review no longer require a course.
- `/jobs` is country-neutral. The scan and apply steps are the same everywhere and the country checks come from the pack. `jobs.country` is empty in the settings template and asked once. Adzuna search takes its default country from `jobs.country`; the Dutch-language guess and the euro labels appear for the Netherlands only, and a country Adzuna does not offer gets a plain message.
- Setup titles and times. Step M3 is "Courses and projects", M6 is "Career and job search", and M1 takes 2 minutes. The essentials take about 24 minutes for an MBA, a degree or something else, 22 for online learners and 21 for people who work. Step titles come from the code, not from your saved progress file.
- The settings template (`config/brain.json`) has `learner` and `packs` (`["core"]`), no `school` block (the programme note replaces it, and older settings still work), an empty `jobs.country`, and a time zone that setup reads from your computer.
- Recipient classes keep their names (they are stored in your drafts), but the wording now fits learners and workers outside a school: `faculty` is teachers, tutors, supervisors and mentors, `school-staff` is programme or provider staff, `peer` includes course-mates and team-mates, `professional` includes managers and clients. Setup asks which groups you write to.

### Upgrades
Each upgrade runs once, after the restore point is saved, and tells you what it did. The update shows this list before you say yes. Upgrades marked "asks you first" are not run by the update: afterwards Claude explains each one, proposes what makes sense, and changes your notes only if you approve.
- `0001-remove-canvas`: removes the retired Canvas connection from your tools list, if you had switched it on, and adds a task if you built the Canvas sync skill.
- `0002-learner-and-packs`: if you started on Alterbrain 0.1, records that you are doing an MBA and switches on the MBA and Netherlands packs you already use.
- `0003-programme-note` (asks you first, after the update): if your settings name a school or programme, offers to make a programme note from them and link your courses to it. Nothing is changed until you say yes, you can skip it or do it later, and your old settings stay.
- `0004-old-pack-paths`: checks the skills and helpers you built, and your identity notes, for links to Alterbrain files that moved, and adds a task if it finds any. It changes none of them.
- `0005-moved-file-edits`: looks for edits you made to Alterbrain files that have a new place (see Moved) and adds a task to carry them over if there are any. It changes no file.
- `0006-brand-to-template` (asks you first, after the update): if you set up a personal style for your documents, offers to turn it into a template you can attach to courses and projects. Your style folder is never changed and keeps working as your default.
- `0007-routine-notes` (asks you first, after the update): if your build list already has scheduled jobs such as a morning brief or a weekly contacts check, offers to give each one a routine note, so you can see it, move it to another computer and notice when it stops. Notes start paused until the job records its runs; nothing on your computer or server is scheduled or changed.
- If you edited one of the moved files, the update offers to carry your edits over.

## [0.1.1] - 2026-10-07

### Added
- Rate guard (`rate_guard` hook, `system/catalogue/limits.json`, `config/limits.json`, `rate-guard.mjs`): usage limits for tools that can get an account restricted, with LinkedIn built in. It counts each action after it ran and stops one that is over a daily, weekly, weekday or minimum-gap limit, saying which limit, how much is used and when it resets. A CAPTCHA, security check or similar warning pauses the tool for 24 hours and halves its limits for 14 days; a second warning switches it to draft-only until you lift that. An action whose result is unknown is never repeated for 24 hours. Default LinkedIn limits are deliberately cautious for student accounts (for example 15 connection requests a day). You can lower any limit; raising one needs `accept_risk`. Other servers can be added as data only. The usage record lives in `state/local/rate-guard/` (not backed up, not editable by Claude). Adapted from the framework author's own LinkedIn guard.
- Exposure-based privacy (ADR 0018): your brain stores what you tell it, including sensitive facts, instead of stripping them. A short never-store list stays out of everything saved (passwords and keys, card and bank account numbers, ID numbers, security-question answers). Every fact has a public or private visibility, and anything that leaves your computer uses public facts only unless you say yes for that draft. Other people's notes hold business facts by default. The privacy guide states the trade-off: Claude processes your vault in sessions and it is stored in your private GitHub repository.
- LinkedIn data-portability blueprint (official member data, no scraping) and portable critique-panel prompts in `docs/critique-panel-prompts.md`.

### Changed
- The assistant is called Twin by default (Juno and Atlas are offered as alternatives).
- Voice read-back: you first see what was learned about your writing and can correct it, then read a short sample in your voice, and only then are asked whether it sounds like you.

### Fixed
- The git guard no longer treats output redirections (`2>&1`, `> file`) as git arguments, so `git push 2>&1` is allowed while `git push --force 2>&1` is still blocked.
- The path guards recognise backslash paths on macOS and Linux.
